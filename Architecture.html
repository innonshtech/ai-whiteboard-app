🔀 API Boundary — Who Calls What

This is the most important thing to get right. The wrong client calling the wrong backend is the most common source of bugs in multi-backend projects.
ClientCalls Node.js?Calls FastAPI?Uses WebSocket?Uses WebRTC?
IFP Panel App ✅ Yes — all non-AI APIs ✅ Yes — all 11 AI tools + OCR + Voice ✅ Yes — interactive classroom (teacher side) ✅ Yes — recording capture, live class broadcast
Teacher App ✅ Yes — all APIs 🚫 No — zero AI calls in Phase 1 🚫 No 🚫 No
Student App ✅ Yes — all APIs 🚫 No — zero AI calls in Phase 1 ✅ Yes — live class (student side — polls, raise hand) ✅ Yes — live class viewer (receive stream)
Admin Portal ✅ Yes — all admin APIs 🚫 No 🚫 No 🚫 No
💡 Panel → AI flow: Panel App calls Node.js → Node.js proxies the request to FastAPI → FastAPI returns AI response → Node.js forwards to Panel. This keeps FastAPI internal (not directly exposed to the internet).

⚡ Real-Time Architecture — Interactive Classroom (M3)

This is the most complex non-AI piece. 40+ students connecting simultaneously. Pre-decide this before writing a single line of M3 code.

WebSocket Room Structure

room: "class_{classId}_{date}"
├── teacher (1 socket)
└── students (up to 40 sockets)

Events emitted by teacher:
├── poll:create → all students
├── quiz:start → all students
├── student:pick → broadcast
└── whiteboard:sync → all students

Events emitted by students:
├── hand:raise → teacher
├── poll:vote → teacher
├── emoji:react → broadcast
└── canvas:draw → teacher

Connection Handling Rules

  • Each classroom = one Socket.io room. Teacher joins on class start, students join on app open.
  • On student disconnect — auto-rejoin with last state (raise hand queue preserved).
  • Attendance is marked server-side when student joins the room — not client-side.
  • Collaborative drawing: use operational transform (OT) or last-write-wins per stroke ID.
  • Redis pub/sub if backend scales to multiple Node.js instances (horizontal scaling).
  • Max 40 students per room — enforce server-side on join attempt.

🤖 AI Pipeline — How a Request Flows (Panel → FastAPI)

Follow this exact flow for every AI feature. Do not call FastAPI directly from the Panel — always go through Node.js.
1
Teacher clicks "Generate Quiz" on the Panel
Panel App collects inputs — topic, class, difficulty, question count. Sends POST request to Node.js backend.
POST /api/ai/quiz
{ topic: "Photosynthesis", class: "8", difficulty: "medium", count: 10 }
2
Node.js validates and proxies to FastAPI
Node.js authenticates the JWT, checks if the school's AI plan is active, then forwards to FastAPI internal network.
POST http://gyoash-ai:8000/ai/quiz
Authorization: Internal-Key {INTERNAL_SECRET}
{ ...same payload + schoolId, teacherId }
3
FastAPI calls the LLM
FastAPI builds the prompt using LangChain, calls OpenAI GPT-4o (or Gemini as fallback), parses the response into structured JSON.
LangChain → OpenAI GPT-4o
Prompt template: quiz_generator.prompt
Returns: [ { question, options, answer, explanation } × 10 ]
4
FastAPI returns to Node.js → Node.js returns to Panel
FastAPI sends structured JSON back. Node.js optionally logs usage (tokens used, school, teacher). Returns to Panel App.
200 OK
{ questions: [...], tokensUsed: 847, model: "gpt-4o" }
5
Panel renders the quiz on the whiteboard canvas
Quiz is displayed as interactive cards on the canvas. Teacher edits if needed, then pushes to students via WebSocket.

🗄️ Database — PostgreSQL Schema Overview

One PostgreSQL database. All tables live here. Managed via Prisma migrations from gyoash-backend.

👤 Auth & Users

  • users (id, email, phone, role, schoolId, createdAt)
  • sessions (id, userId, token, expiresAt)
  • audit_logs (id, userId, action, ip, createdAt)

🏫 School & Admin

  • schools (id, name, code, branding, plan, createdAt)
  • branches (id, schoolId, name, location)
  • panels (id, branchId, licenseKey, status, health)
  • classrooms (id, branchId, panelId, name)

📚 Academic

  • classes (id, schoolId, grade, section, teacherId)
  • subjects (id, classId, name, board)
  • timetable (id, classId, subjectId, day, startTime)
  • students (id, userId, classId, rollNo, parentId)

📝 Homework & Assessments

  • homework (id, classId, title, dueDate, attachments)
  • submissions (id, homeworkId, studentId, files, marks)
  • assessments (id, classId, title, totalMarks, scheduledAt)
  • results (id, assessmentId, studentId, marks, feedback)

🎓 Classroom & Attendance

  • live_sessions (id, classId, startedAt, endedAt, recordingUrl)
  • attendance (id, sessionId, studentId, status, markedAt)
  • polls (id, sessionId, question, options, responses)
  • raise_hand_queue (id, sessionId, studentId, position)

🤖 AI Usage

  • ai_logs (id, schoolId, teacherId, tool, tokensUsed, model, createdAt)
  • ai_plans (id, schoolId, plan, monthlyTokenLimit, usedTokens)

📁 Content & Files

  • recordings (id, sessionId, url, duration, size, status)
  • content_items (id, schoolId, type, board, grade, subject, chapter, url)
  • whiteboard_sessions (id, classId, data, version, savedAt)

🔔 Notifications

  • notifications (id, userId, type, title, body, read, createdAt)
  • device_tokens (id, userId, token, platform, updatedAt)
⚠️ This is a starting schema. The actual Prisma schema file in gyoash-backend is the single source of truth. Never modify the DB directly — always use Prisma migrations.

✅ Day 1 Checklist — Per Developer Role

Every developer should be able to run their part of the system locally by end of Day 1. This checklist makes that happen.

🖥️ Panel Developer (React + Canvas)

  • Clone gyoash-panel repo
  • Run npm install
  • Copy .env.example → .env, fill VITE_API_URL
  • Run npm run dev — panel opens on localhost:5173
  • Verify canvas renders (blank whiteboard visible)
  • Confirm Node.js backend is running (ping /api/health)
  • Read Phase1_Coverage.html — M1 and M2 sections
  • Start with: Auth screen → canvas shell → basic pen tool

📱 Mobile Developer (React Native)

  • Clone gyoash-teacher-app and gyoash-student-app
  • Run npm install in both
  • Install Expo CLI globally: npm i -g expo-cli
  • Copy .env.example → .env in both repos
  • Run npx expo start in each
  • Scan QR with Expo Go app on physical device
  • Verify login screen renders on device
  • Add google-services.json (Firebase) from GYOASH
  • Start with: Login flow → Dashboard shell

⚙️ Backend Developer (Node.js)

  • Clone gyoash-backend repo
  • Run npm install
  • Start PostgreSQL locally (Docker: docker-compose up db)
  • Start Redis locally (Docker: docker-compose up redis)
  • Copy .env.example → .env, fill DATABASE_URL + REDIS_URL
  • Run npx prisma migrate dev — creates DB tables
  • Run npx prisma db seed — seeds base data
  • Run npm run dev — server on localhost:3000
  • Hit GET /api/health → should return 200 OK
  • Start with: Auth endpoints (register, login, JWT refresh)

🤖 AI Developer (Python + FastAPI)

  • Clone gyoash-ai repo
  • Create virtual env: python -m venv venv
  • Activate: venv\Scripts\activate (Windows)
  • Install deps: pip install -r requirements.txt
  • Copy .env.example → .env, fill OPENAI_API_KEY
  • Run: uvicorn main:app --reload --port 8000
  • Open http://localhost:8000/docs — FastAPI auto-docs
  • Test POST /ai/quiz with a sample payload
  • Verify OpenAI response comes back correctly
  • Start with: /ai/quiz → /ai/lesson-plan → /ai/explain

🌐 Admin Developer (React Web)

  • Clone gyoash-admin repo
  • Run npm install
  • Copy .env.example → .env, fill VITE_API_URL
  • Run npm run dev — admin portal on localhost:5174
  • Confirm backend is running (Node.js on :3000)
  • Login with seeded Super Admin credentials
  • Start with: Login → School registration → Panel registration
